# 精读：采样器体系（llama-sampler.cpp）

> 日期：2026-08-13 | 核心文件：`src/llama-sampler.cpp`（3883 行）+ `include/llama.h:1242`
> 前置：已读 `00`，知道 `common_sampler_sample`(common/sampling.cpp:540) 会调用采样链。

## 作用

从模型的 logits（`llama_token_data_array cur_p`）里挑出要生成的 token。llama.cpp 把每种采样策略实现为**一个可插拔的采样器**，再串成一条链顺序执行。

## 核心抽象：`llama_sampler_i`（接口，`llama.h:1242`）

每个采样器是一个对象 `{ iface, ctx }`，`iface` 是函数指针表，定义四种行为：

| 回调 | 作用 | 必选 |
|---|---|---|
| `name` | 采样器名字 | 可空 |
| `apply` | **核心**：就地修改 `cur_p`（过滤/重排/改概率） | 必选 |
| `accept` | 接受已选 token，更新内部状态（惩罚、grammar 推进） | 可空 |
| `reset` | 重置状态（新序列时） | 可空 |
| `clone`/`free` | 复制/释放 | 可空 |

> 另有 `backend_*` 一组后端口（实验性）：把采样算子直接加进 ggml 计算图，在 GPU 上跑，避免 logits 回 CPU。

## 链式组合（`llama_sampler_chain`）

`llama_sampler_chain_apply`（`llama-sampler.cpp:642`）逐个调用链上采样器的 `apply`：
```
for (每个采样器)  llama_sampler_apply(smpl, cur_p);   // 串行就地改 cur_p
```
- **顺序敏感**：前一个的输出是后一个的输入。典型顺序：logit_bias -> penalties -> top_k -> top_p/min_p -> temp -> dist
- `accept` 同理逐个调用（`llama-sampler.cpp:630`），让有状态的采样器（DRY、grammar、重复惩罚）知道选了哪个 token
- 链本身也是 `llama_sampler_i`，可嵌套/克隆

## 一个具体样例：top_k（`llama-sampler.cpp:1246`）

```cpp
struct llama_sampler_top_k { const int32_t k; };          // 仅存参数 k

static void llama_sampler_top_k_apply(smpl, cur_p) {
    llama_sampler_top_k_impl(cur_p, k);   // 只保留得分最高的 k 个候选
}
// + clone/free/name 等样板
static struct llama_sampler_i llama_sampler_top_k_i = { name, accept, apply, reset, clone, free, ... };
```
每个采样器实例化时 `llama_sampler_init(iface_top_k, new top_k{k})`。

## 与 common 层的关系

- `common/sampling.cpp:540` `common_sampler_sample` 是**高层入口**：取 logits -> 建 `cur_p` -> 调 `llama_sampler_apply(chain)` -> 返回 token
- `common/sampling.cpp` 里 `common_sampler_init` 按用户的 `llama_sampler_params` 把上面各采样器按标准顺序拼成链
- server 层 `post_decode` 只调 `common_sampler_sample`，不关心链内部

## 图视角小结

- **设计优雅处**：统一接口 + 链式组合，新增采样策略只需写一个 `iface` + 一个 `apply`，无需改调用方。
- **有状态 vs 无状态**：greedy/top_k 无状态（apply 不改自身）；penalties/grammar/dry 有状态（靠 accept 记录历史）。
- **CPU/后端分离**：默认 CPU 采样；`backend_*` 支持把算子塞进图在 GPU 跑，是长上下文提效方向。
