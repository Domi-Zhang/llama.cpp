## 作用

从模型的 logits（`llama_token_data_array cur_p`）里挑出要生成的 token。llama.cpp 把每种采样策略实现为**一个可插拔的采样器**，再串成一条链顺序执行。

### 为什么不全选 argmax？

模型每一步输出的是词表上每个 token 的"logit"，最朴素的挑法是 `argmax(logits)`，即贪心解码（greedy）。但它有三个问题：

1. **重复循环**：贪心确定性地选最大，模型一旦在某处陷入"我说->我->说"的局部吸引子，就跳不出来。采样引入随机性，相当于在每步给系统一点"扰动"，能打破循环。
2. **多样性丢失**：对同一个 prompt，贪心永远输出同一句。聊天场景下用户期望"换一种说法"的体验；做数据合成时期望覆盖多种风格。采样能让同一 prompt 产出多条不同续写。
3. **质量并非最高**：研究表明，在开放式生成（story、对话）里，适度的随机性让人感觉更"自然"；纯贪心常显得呆板。当然太随机又会乱，所以核心问题是**怎么控制随机的程度**。

采样器体系就是一组旋钮：先用 temperature 调"尖锐度"，再用 top_k/top_p/min_p 等过滤掉不合理候选，最后用 dist 按概率抽。组合得当，既不循环也不胡言。

## 核心抽象：`llama_sampler_i`（接口，`llama.h:1242`）

每个采样器是一个对象 `{ iface, ctx }`（`include/llama.h:1275`），`iface` 是函数指针表，`ctx` 是该采样器自己的状态。定义如下（`include/llama.h:1242`）：

```c
struct llama_sampler_i {
    const char *           (*name)  (const struct llama_sampler * smpl);                                 // can be NULL
    void                   (*accept)(      struct llama_sampler * smpl, llama_token token);              // can be NULL
    void                   (*apply) (      struct llama_sampler * smpl, llama_token_data_array * cur_p); // required
    void                   (*reset) (      struct llama_sampler * smpl);                                 // can be NULL
    struct llama_sampler * (*clone) (const struct llama_sampler * smpl);                                 // can be NULL if ctx is NULL
    void                   (*free)  (      struct llama_sampler * smpl);                                 // can be NULL if ctx is NULL
    // [EXPERIMENTAL] backend_* 一组：把采样算子加进 ggml 计算图，在 GPU 上跑
    bool (*backend_init)(struct llama_sampler * smpl, ggml_backend_buffer_type_t buft);
    void (*backend_accept)(struct llama_sampler * smpl, struct ggml_context * ctx, struct ggml_cgraph * gf, struct ggml_tensor * selected_token);
    void (*backend_apply)(struct llama_sampler * smpl, struct ggml_context * ctx, struct ggml_cgraph * gf, struct llama_sampler_data * data);
    void (*backend_set_input)(struct llama_sampler * smpl);
};
```

| 回调 | 作用 | 必选 |
|---|---|---|
| `name` | 采样器名字 | 可空 |
| `apply` | **核心**：就地修改 `cur_p`（过滤/重排/改概率） | 必选 |
| `accept` | 接受已选 token，更新内部状态（惩罚、grammar 推进） | 可空 |
| `reset` | 重置状态（新序列时） | 可空 |
| `clone`/`free` | 复制/释放 | 可空 |

### 为什么用函数指针表而不是 C++ 虚函数？

1. **C API 导出**：`llama.h` 是纯 C 头文件，要在 `extern "C"` 下被其它语言（Python、Go、Rust）绑定。虚函数表是 C++ ABI 私有的，不能跨编译器/版本稳定暴露；函数指针表是普通结构体，任何 C 编译器都能拿。
2. **显式控制内存**：`ctx` 是 `void *`，由各采样器自己 `new`/`delete` 自己的类型。`free` 回调里 `delete (llama_sampler_top_k *) smpl->ctx;`（见 `llama-sampler.cpp:1266`）。这样生命周期完全由 C API 控制，不依赖 C++ 运行时。
3. **`clone` 支持并行序列**：一条链要被多个序列共享时（比如 speculative decoding 的多条 draft），调 `clone` 给每个序列复制一份有状态采样器（penalties 的历史、mirostat 的 mu），互不污染。无状态的（top_k）clone 时只需新建同参数实例。

> 与 C++ 虚函数对比一句：虚函数能做"多态 + RAII"，但 ABI 不稳；函数指针表是"手动 vtable"，丑但稳，是 C 库导出多态对象的标准做法。

> 另有 `backend_*` 一组后端口（实验性）：把采样算子直接加进 ggml 计算图，在 GPU 上跑，避免 logits 回 CPU。

## 链式组合（`llama_sampler_chain`）

`llama_sampler_chain_apply`（`llama-sampler.cpp:642`）逐个调用链上采样器的 `apply`：

```cpp
for (auto & smpl : chain->samplers) {
    llama_sampler_apply(smpl.ptr, cur_p);   // 串行就地改 cur_p
}
```

- **顺序敏感**：前一个的输出是后一个的输入。
- `accept` 同理逐个调用（`llama-sampler.cpp:630`），让有状态的采样器（DRY、grammar、重复惩罚）知道选了哪个 token。
- 链本身也是 `llama_sampler_i`，可嵌套/克隆。

### 顺序敏感性：为什么"先 A 再 B"和"先 B 再 A"结果不同？

链是串行管线，每个采样器看到的是上游处理过的 `cur_p`。两个采样器的组合不可交换，当且仅当至少一个改变了"哪些候选保留"或"概率的相对关系"。

**例 1：top_k + temperature（看似无关）**

`top_k` 按 logit 排序选前 k 个，`temperature` 是 logit 的正单调缩放（`logit /= T`）。单调缩放不改变 logit 的大小顺序，所以：

- 先 `top_k(2)` 再 `temp(0.5)`：从 [5,4,3,1] 选前 2 个得 [5,4]，缩放为 [10,8]。
- 先 `temp(0.5)` 再 `top_k(2)`：缩放为 [10,8,6,2]，选前 2 个得 [10,8]。

结果一样。这对组合顺序无关。

**例 2：top_p + temperature（真正敏感）**

`top_p` 基于 softmax 后的概率截断，而 temperature 改变 softmax 后的概率分布尖锐度。用统一例子 logits=[5,4,3,1]：

- **先 `top_p(0.9)` 再 `temp(0.5)`**：
  - 原始 softmax: P=[0.6574, 0.2418, 0.0889, 0.0120]
  - 累积：A=0.6574 (<0.9), A+B=0.8992 (<0.9), A+B+C=0.9881 (>=0.9)，保留 A,B,C（3 个）
  - 对 [5,4,3] 应用 T=0.5 得 [10,8,6]，重 softmax: P=[0.8668, 0.1173, 0.0159]
- **先 `temp(0.5)` 再 `top_p(0.9)`**：
  - 缩放为 [10,8,6,2]，softmax: P=[0.8668, 0.1173, 0.0159, 0.0003]
  - 累积：A=0.8668 (<0.9), A+B=0.9841 (>=0.9)，保留 A,B（2 个）

第一种保留 3 个候选，第二种只保留 2 个候选。**顺序影响结果**。

直觉：temperature 在 top_p 之前，会让分布更尖锐，top_p 的"核心"更小，截断更早；temperature 在 top_p 之后，top_p 看到的是原始较平的分布，会保留更多候选，然后 temperature 再把它们的概率重新拉开。

**经验法则**：先做"基于 logit 的过滤"（top_k、top_n_sigma、logit_bias、penalties），再做"基于概率的过滤"（top_p、min_p、typical），最后做 temperature 和 dist。`common/sampling.cpp` 的默认链正是这个顺序（见下文）。

## apply 的"就地修改 cur_p"约定

`apply` 的签名是 `void apply(smpl, cur_p)`，没有返回值。所有改动都直接写到 `cur_p` 指向的数组里。`cur_p` 的类型是 `llama_token_data_array`（`include/llama.h:213`）：

```c
typedef struct llama_token_data {
    llama_token id; // token id
    float logit;    // log-odds of the token
    float p;        // probability of the token
} llama_token_data;

typedef struct llama_token_data_array {
    llama_token_data * data;  // 指针可被采样器修改（如 top_k 把 data 前移）
    size_t size;
    int64_t selected;         // 数据数组里的索引（不是 token id）
    bool sorted;              // 不要假设已排序，必须先检查这个标志
} llama_token_data_array;
```

采样器修改 `cur_p` 的几种方式：

1. **缩小 size**：`top_k` 直接 `cur_p->size = k;`（`llama-sampler.cpp:333`），等价于"逻辑删除"尾部。
2. **移动 data 指针**：`xtc` 把 `cur_p->data += pos_last; cur_p->size -= pos_last;`（`llama-sampler.cpp:2146`），跳过被删的头部。
3. **改 logit/p 字段**：`temp` 改 logit（`llama-sampler.cpp:285`），`penalties` 改 logit（`llama-sampler.cpp:2691`）。
4. **置 `selected`**：`greedy`、`dist`、`mirostat` 把选中的索引写到 `cur_p->selected`，由调用方读取。

### sorted 标志的用途

`cur_p->sorted` 表示 `data[0..size]` 是否已按 logit 降序排好。注释明确警告"不要假设已排序，必须先检查"（`include/llama.h:219`）。原因：

- 排序是 O(n log n) 的开销，词表动辄 5-13 万，能省则省。
- `top_k`、`top_p`、`min_p` 需要"前 k 个最大"或"按概率累积"，必须排序。它们会先 `if (!cur_p->sorted) sort(...)`，排完置 `sorted = true`，下游就能复用。
- `penalties` 改了 logit，会置 `sorted = false`（`llama-sampler.cpp:2699`），告诉下游"我刚改过，你得重排"。
- `typical` 用了不同的排序键（信息量距离），排完置 `sorted = false`（`llama-sampler.cpp:1755`），因为它没按 logit 排。

这种"懒排序 + 标志位"是采样链能跑得快的关键。

## 一个具体样例：top_k（`llama-sampler.cpp:1246`）

```cpp
struct llama_sampler_top_k : public llama_sampler_backend {
    const int32_t k;                                          // 仅存参数 k
};

static void llama_sampler_top_k_apply(smpl, cur_p) {
    auto * ctx = (llama_sampler_top_k *) smpl->ctx;
    llama_sampler_top_k_impl(cur_p, ctx->k);                  // 只保留得分最高的 k 个候选
}
// + clone/free/name 等样板
static struct llama_sampler_i llama_sampler_top_k_i = {
    /* .name = */ llama_sampler_top_k_name,
    /* .accept = */ nullptr,
    /* .apply = */ llama_sampler_top_k_apply,
    /* .reset = */ nullptr,
    /* .clone = */ llama_sampler_top_k_clone,
    /* .free = */ llama_sampler_top_k_free,
    /* .backend_* = */ ...,
};
```

每个采样器实例化时 `llama_sampler_init(&llama_sampler_top_k_i, new llama_sampler_top_k{k})`（`llama-sampler.cpp:1328`）。`top_k_impl` 的实现很简单（`llama-sampler.cpp:317`）：若未排序就调 `partial_sort_inplace` 取前 k，然后 `cur_p->size = k` 截断。

## 各采样器公式与数值例子

下面所有例子统一用 logits = [5.0, 4.0, 3.0, 1.0]，对应 token A, B, C, D。

### 基础 softmax（T=1，作为基准）

公式：

```
p_i = exp(l_i - max_l) / sum_j(exp(l_j - max_l))
```

减 `max_l` 是数值稳定技巧，不改变结果。手算：

- max_l = 5.0
- exp(0)=1, exp(-1)=0.3679, exp(-2)=0.1353, exp(-4)=0.0183
- sum = 1.5215
- 归一化：P = [0.6574, 0.2418, 0.0889, 0.0120]

后面所有"基于概率"的采样器都从这组 P 出发。

### 1. temperature（`llama-sampler.cpp:1871`，impl 在 265）

**公式**：`l_i' = l_i / T`，然后 softmax(l')。

**直觉**：T 控制 softmax 的"尖锐度"。T 越小，最高概率的 token 越被放大（趋向贪心）；T 越大，分布越平均（趋向均匀采样）。T=1 不变。T<=0 是特例：源码直接把所有非最大 logit 设为 -INFINITY（`llama-sampler.cpp:266-282`），等价于贪心。

**手算对比表**（用 [5.0, 4.0, 3.0, 1.0]）：

| T | logits' | P(A) | P(B) | P(C) | P(D) | 行为 |
|---|---|---|---|---|---|---|
| 0.5 | [10, 8, 6, 2] | 0.8668 | 0.1173 | 0.0159 | 0.0003 | 尖锐，接近贪心 |
| 1.0 | [5, 4, 3, 1] | 0.6574 | 0.2418 | 0.0889 | 0.0120 | 原始分布 |
| 2.0 | [2.5, 2, 1.5, 0.5] | 0.4740 | 0.2876 | 0.1744 | 0.0641 | 平坦，更随机 |

注意 T=0.5 时 P(D) 几乎为 0，T=2 时连最差的 D 也有 6% 的概率被选中。

**源码细节**：`llama_sampler_temp_impl`（`llama-sampler.cpp:265`）就地改 `cur_p->data[i].logit /= temp`，不重算 p（p 由后续 softmax 算子或 dist 算）。

### 2. top_k（`llama-sampler.cpp:1246`，impl 在 317）

**公式**：保留 logit 最高的 k 个候选，其余丢弃，再归一化。

**直觉**：硬截断。简单粗暴地砍掉长尾，强制只在前 k 个里选。优点是计算便宜（partial_sort 取前 k 是 O(n log k)），缺点是 k 是固定常数，不适应分布形状-有时前 3 个就占了 99% 概率，有时前 50 个还很分散。

**手算**（k=2）：

- 排序：[5, 4, 3, 1] -> A, B, C, D
- 保留 A, B，丢弃 C, D
- 重新归一化（基于原 P）：sum = 0.6574 + 0.2418 = 0.8992
- P'(A) = 0.6574/0.8992 = 0.7311
- P'(B) = 0.2418/0.8992 = 0.2689

注意 top_k 本身不做归一化，它只截断 size。归一化是后续 softmax 或 dist 隐式做的。

**源码细节**：`llama_sampler_top_k_impl`（`llama-sampler.cpp:317`）调 `partial_sort_inplace` 取前 k 后 `cur_p->size = k`（行 333）。

### 3. top_p / nucleus sampling（`llama-sampler.cpp:1339`）

**公式**：按概率降序排列，累积概率首次达到 p 时停止，保留这些候选。

**直觉**：自适应截断。分布尖锐时保留少，分布平坦时保留多。比 top_k 更智能，是开放式生成最常用的策略之一。论文 "The Curious Case of Neural Text Degeneration"（Holtzman et al., 2019）。

**手算**（p=0.9）：

- 排序后 P = [A:0.6574, B:0.2418, C:0.0889, D:0.0120]
- 累积：
  - A: 0.6574（< 0.9，继续）
  - A+B: 0.8992（< 0.9，继续）
  - A+B+C: 0.9881（>= 0.9，停）
- 保留 A, B, C（last_idx=3）

若 p=0.85：A+B=0.8992 >= 0.85，保留 A, B。

**源码细节**：`llama_sampler_top_p_apply`（`llama-sampler.cpp:1351`）先 `softmax_impl(cur_p, false)`（不排序只算 p），再用自适应 top-k 启发式避免全排序（行 1366-1373）。累积时检查 `cum_sum >= ctx->p && i + 1 >= ctx->min_keep`（行 1384），`min_keep` 是保底保留数。

### 4. min_p（`llama-sampler.cpp:1533`）

**公式**：保留 `p_i >= min_p * p_max` 的候选，其中 `p_max` 是最大候选概率。

**直觉**：相对于最大概率的阈值。比 top_p 优点是**对分布形状不敏感**：top_p 在分布很平时（比如均匀分布）会保留几乎全部候选，没起到截断作用；min_p 永远按"最大概率的几分之一"来砍，无论分布形状如何都能滤掉长尾。

**手算**（min_p=0.1）：

- p_max = 0.6574（A 的概率）
- 阈值 = 0.1 * 0.6574 = 0.06574
- 保留：A(0.6574 >= 0.06574) ✓, B(0.2418) ✓, C(0.0889) ✓, D(0.0120 < 0.06574) ✗
- 保留 A, B, C

若 min_p=0.5：阈值 = 0.3287，只保留 A。

**源码细节**：`llama_sampler_min_p_apply`（`llama-sampler.cpp:1543`）用 logit 域等价计算：`min_logit = max_logit + logf(ctx->p)`（行 1560、1583），避免显式算 softmax。因为 `log(p_i) = l_i - logsumexp`，`p_i >= p * p_max` 等价于 `l_i >= l_max + log(p)`。这是采样器里常见的"对数域技巧"。

### 5. typical / locally typical sampling（`llama-sampler.cpp:1767`）

**公式**：

1. 算 softmax 得 P，算熵 `H = -sum_i p_i * log(p_i)`
2. 每个 token 的"信息量" `I_i = -log(p_i)`
3. 算"典型距离" `d_i = |I_i - H|`
4. 按 d_i 升序排，累积概率到 p 截断

**直觉**：反直觉地排除两类极端 token-概率极高的（信息量 << 熵，太"意料之中"，容易导致重复）和概率极低的（信息量 >> 熵，太"意料之外"，容易跑题），保留"信息量接近熵"的中间派。论文 "Locally Typical Sampling"（Meister et al., 2022)。

**手算**（p=0.9）：

- P = [0.6574, 0.2418, 0.0889, 0.0120]
- 熵 H = -(0.6574*ln(0.6574) + 0.2418*ln(0.2418) + 0.0889*ln(0.0889) + 0.0120*ln(0.0120))
       = -(0.6574*(-0.4197) + 0.2418*(-1.4197) + 0.0889*(-2.4197) + 0.0120*(-4.4197))
       = 0.2759 + 0.3432 + 0.2152 + 0.0531
       = 0.8874 (nats)
- 信息量 I_i = -ln(p_i)：A=0.4197, B=1.4197, C=2.4197, D=4.4197
- 距离 d_i = |I_i - H|：A=0.4678, B=0.5323, C=1.5323, D=3.5323
- 按距离升序：A, B, C, D（顺序没变，因为本例里 A 既是最典型又是最高概率；若 A 概率极端高，会被排到后面）
- 累积：A=0.6574, A+B=0.8992, A+B+C=0.9881 > 0.9，保留 A, B, C

**什么时候 typical 会"反直觉地排除最高概率"？** 假设 P=[0.99, 0.005, 0.003, 0.002]，H 很小（约 0.06 nats），A 的信息量 -ln(0.99)=0.01 距离 H 0.05，B 的信息量 -ln(0.005)=5.3 距离 H 5.24-实际上这时 A 仍然最典型。typical 的"反直觉"主要体现在它会排除概率极低的长尾（D 这种），即使它们的 logit 还不算太差。和 top_p 相比，typical 在分布有"双峰"时表现不同，会更倾向于在两个峰里各选一些。

**源码细节**：`llama_sampler_typical_apply`（`llama-sampler.cpp:1698`）先 `softmax_impl(cur_p, true)` 排序算 p 和熵，然后用 `std::sort` 按距离重排（行 1726），最后置 `sorted = false`（行 1755）因为排序键不是 logit。

### 6. penalties: frequency/presence/repeat（`llama-sampler.cpp:2730`）

**公式**（对在最近 `penalty_last_n` 个 token 中出现过的候选）：

```
if logit_i <= 0:
    logit_i *= penalty_repeat
else:
    logit_i /= penalty_repeat
logit_i -= count_i * penalty_freq + (count_i > 0) * penalty_present
```

其中 `count_i` 是该 token 在最近窗口内的出现次数。

**直觉**：
- **repeat penalty**（`penalty_repeat`，>1 时生效）：把出现过 token 的 logit 缩小。源码注释（`llama-sampler.cpp:2688-2689`）解释为什么用"乘/除"而不是论文里的"除"：纯除法会让负 logit 反而变大概率，所以负 logit 改用乘法（也是缩小）。
- **frequency penalty**（`penalty_freq`）：按出现次数线性扣分，出现越多扣得越多。
- **presence penalty**（`penalty_present`）：只要出现过就扣固定分（count > 0 即扣）。

**手算**：设 token A 在最近 64 个 token 内出现 3 次，参数 `penalty_repeat=1.1, penalty_freq=0.05, penalty_present=0.1`：

- 原 logit A = 5.0
- 5.0 > 0，所以 `logit /= 1.1` -> 4.5455
- `logit -= 3 * 0.05 + 1 * 0.1` = 4.5455 - 0.25 = **4.2955**

对比未出现过的 B（logit=4.0 不变）。原本 A 比 B 高 1.0，惩罚后只高 0.2955。如果 A 出现 10 次：`5.0/1.1 - 10*0.05 - 0.1 = 4.5455 - 0.6 = 3.9455`，反而比 B 低了。

**源码细节**：
- `llama_sampler_penalties_accept`（`llama-sampler.cpp:2638`）维护一个 `ring_buffer<llama_token> prev`（容量 `penalty_last_n`）和 `unordered_map<token, int> token_count`。每次 accept 新 token 时计数+1，若环满则把最老的 token 计数-1。
- `apply` 时遍历 cur_p，对在 `token_count` 里的 token 改 logit（行 2678-2697），最后置 `sorted = false`（行 2699），因为 logit 变了排序可能乱。
- penalties 是**有状态采样器**，所以 `clone` 会复制 `prev` 环（行 2720），让并行序列各自维护历史。

### 7. mirostat / mirostat v2（`llama-sampler.cpp:2294 / 2398`）

**直觉**：反馈控制。目标：让生成文本的"惊讶度"（perplexity，用 -log2(p) 度量）稳定在用户设定的 `tau` 附近。内部维护一个误差积分变量 `mu`（初始 `2*tau`），每步：

1. softmax 算概率
2. **mirostat v1**：用 top-m 候选估 Zipf 系数 `s_hat`（`llama-sampler.cpp:2241-2247`），由 `mu` 和 `s_hat` 算出 top-k 的大小 `k`（行 2251），截断后采样。
3. **mirostat v2**：更简单，直接用 `-log2(p) > mu` 截断（`llama-sampler.cpp:2349-2351`），即"惊讶度超过 mu 的丢掉"。
4. 采样后算实际惊讶度 `observed = -log2(p_selected)`，误差 `e = observed - tau`。
5. 更新 `mu = mu - eta * e`（`llama-sampler.cpp:2265` / `2368`）。

如果实际太惊讶（observed > tau），mu 减小，下一步截断更严，候选更确定；反之 mu 增大，放松截断。`eta` 是学习率。

**为什么用 perplexity 反馈？** 文本的可读性与"每 token 平均信息量"强相关。太低（贪心）= 重复无聊；太高（纯随机）= 胡言乱语。mirostat 把它锁在目标值，是自适应版本的 temperature + top_k。

**源码细节**：mirostat 是有状态的（`mu` 跨步保留），`reset` 时 `mu = 2*tau`（行 2285）。`accept` 不需要，因为状态在 `apply` 末尾就更新了。

### 8. xtc: exclude top tokens（`llama-sampler.cpp:2175`）

**公式**：以概率 `probability` 触发；触发后把所有 `p_i >= threshold` 的最高概率 token 删掉（保留尾部）。

**直觉**：专门用来打破"老选最优"的惯性。当模型对某 token 信心特别高时，xtc 有概率把整个"高信心区"删掉，强制去次优里选。常见用于创意写作。注意源码限制 `threshold > 0.5` 时直接 return（`llama-sampler.cpp:2122`），避免删太多。

**源码细节**：`llama_sample_xtc_apply`（`llama-sampler.cpp:2118`）用 `std::uniform_real_distribution` 抽随机数决定是否触发（行 2127-2131），触发后 `cur_p->data += pos_last; cur_p->size -= pos_last`（行 2146-2147）跳过被删头部。

### 9. top_n_sigma（`llama-sampler.cpp:2827`）

**公式**：保留 `logit_i >= max_logit - n * std` 的候选，其中 `std` 是所有有效 logit 的标准差。

**直觉**：按"统计显著性"过滤。把 max 当基准，n*std 当容差，只保留在 max 的 n 倍标准差范围内的 token。论文 "Top-n-sigma: Not All Logits Are You Need"。比 top_k/top_p 更"统计学"，对 logit 的绝对尺度不敏感。

**手算**（n=1）：

- mean = (5+4+3+1)/4 = 3.25
- 方差 = ((5-3.25)^2 + (4-3.25)^2 + (3-3.25)^2 + (1-3.25)^2)/4 = 8.75/4 = 2.1875
- std = sqrt(2.1875) = 1.4790
- 阈值 = 5.0 - 1*1.4790 = 3.521
- 保留：A(5.0) ✓, B(4.0) ✓, C(3.0 < 3.521) ✗, D(1.0) ✗
- 保留 A, B

若 n=2：阈值 = 5.0 - 2.958 = 2.042，保留 A, B, C。

**源码细节**：`llama_sampler_top_n_sigma_apply`（`llama-sampler.cpp:2779`）跳过 -INFINITY 的 logit 算 mean/std（行 2792、2804），把低于阈值的 logit 设为 -INFINITY（行 2813）而不是缩小 size-这样保留位置信息，下游采样器仍能按原索引访问。

## 图视角小结

- **设计优雅处**：统一接口 + 链式组合，新增采样策略只需写一个 `iface` + 一个 `apply`，无需改调用方。
- **有状态 vs 无状态**：greedy/top_k/top_p/min_p/temp/typical/top_n_sigma 无状态（apply 不改自身，clone 只新建同参数实例）；penalties/grammar/dry/mirostat/xtc/adaptive_p 有状态（靠 accept 或 apply 内部记录历史），clone 时要复制状态。
- **CPU/后端分离**：默认 CPU 采样；`backend_*` 支持把算子塞进图在 GPU 跑，是长上下文提效方向。`common_sampler_sample` 会先检查后端是否已经采样（`common/sampling.cpp:558`），是则直接返回，跳过整条 CPU 链。
- **顺序敏感性的实践**：penalties 必须在 top_k/top_p 之前（先改 logit 再过滤），temperature 必须在最后（前面基于 logit 排序的采样器对单调缩放不敏感，但 top_p/min_p/typical 基于 softmax 后的概率，temperature 一改就得重算）。`common/sampling.cpp` 默认链顺序正是按这个约束排的。
