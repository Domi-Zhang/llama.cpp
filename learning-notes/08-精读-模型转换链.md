# 精读：模型转换链（HF -> GGUF）

> 日期：2026-08-13
> 核心文件：`convert_hf_to_gguf.py`（入口）+ `conversion/base.py`（基类）+ `conversion/<arch>.py`（各架构）+ `gguf-py/`（GGUF 写库）
> 前置：已读 `07`，GGUF 是 llama.cpp 的模型格式，转换是「PyTorch/HF 权重 -> GGUF」的桥。

## 作用

把 Hugging Face 格式（safetensors + config.json + tokenizer）的模型权重、超参、词表，转成 llama.cpp 能直接加载的 `.gguf` 单文件。每个新架构要能在 llama.cpp 跑，都得先有对应的转换器。

## 流程总览

```
convert_hf_to_gguf.py main()
  ├─ 解析参数 (-o f16/bf16/q8_0/auto)        
  ├─ ModelBase.load_hparams(dir) :1042   读 config.json 得超参
  ├─ get_model_architecture(hparams)     按 model_type 映射到 llama.cpp 架构 (如 LLaMA)
  ├─ get_model_class(...)                 取 conversion/<arch>.py 的类
  ├─ model_instance.write() :1022        核心转换
  │    ├─ prepare_tensors() :785         读 HF 权重 -> 映射为 GGUF 张量名
  │    ├─ prepare_metadata()             组 KV 元数据（arch/超参/词表）
  │    ├─ write_header_to_file()         写 GGUF 头
  │    ├─ write_kv_data_to_file()        写 KV 元数据
  │    └─ write_tensors_to_file()        写张量数据
  └─ 产出 .gguf
```

## 一、架构映射与抽象（`conversion/base.py`）

`ModelBase` 是抽象基类，定义子类必须实现的钩子：

| 方法 | 作用 |
|---|---|
| `set_vocab` | 写词表（BPE/SentencePiece）到 KV |
| `set_gguf_params` | 写超参（维度/层数/头数...）到 KV |
| `set_tensors` | 把 HF 张量按 GGUF 命名规则写入 |
| `modify_tensors` | 预处理某个张量（转置/重命名） |
| `format_tensor_name` | HF 名 -> gguf.MODEL_TENSOR 名映射 |

每个架构一个子类（`conversion/llama.py`、`qwen.py`...），用 `@register("LLaMA", "Llama")` 装饰器注册到名字表，`get_model_class` 按 config 里的 `model_type` 查找。

> 设计：**新增架构 = 写一个新子类**，实现 set_vocab/set_gguf_params/set_tensors 三个钩子，其余复用基类。

## 二、GGUF 文件三段结构（`write()` :1022）

GGUF 是二进制容器，三段写入：
1. **Header**：魔数 `GGUF`、版本、tensor 数量、KV 数量
2. **KV metadata**：统一键值对（架构名、超参、tokenizer 配置、量化类型）
3. **Tensor data**：每个张量的名称、形状、类型、数据（原始 f32/f16 或量化块）

张量名遵循 `gguf.MODEL_TENSOR` 枚举（如 `token_embd.weight`、`blk.0.attn_q.weight`），与 `src/models/llama.cpp:34` `load_arch_tensors` 里 `LLM_TENSOR_*` 一一对应——这也是转换器与加载器能对上的关键约定。

## 三、关键点

- **量化发生在转换时**：`-o q8_0` 等会调用 gguf-py 内部的量化（对应 `06` 的 block 格式），转出的就是已量化权重。
- **懒加载/远程**：`--remote` 直接从 HF 拉文件；`--lazy` 用 safetensors mmap 逐张量读，避免一次载入全部内存。
- **分片**：`--split-max-size` 可把大模型拆成多文件 GGUF。
- **词表**：`--vocab-only` 只导出词表；词表格式（BPE/SPM）决定 `set_vocab` 的分支。
- **与加载器对称**：转换器写什么名/类型，`load_arch_tensors` 就按同样名/类型读，两端必须一致。

## 图视角小结（全链路闭环）

```
conversion (<arch>.py)  ─写─>  GGUF 文件  ─读─>  src/models/<arch>.cpp load_arch_tensors
   HF 张量名/超参              三段结构           llama.cpp 张量名 LLM_TENSOR_*
```
- 转换链是「模型入库」的入口，`docs/development/HOWTO-add-model.md` 是官方教程
- 理解它，就能理解「为什么新增一个模型要改转换器 + 加载器 + 构图」三处
