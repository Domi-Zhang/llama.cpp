```

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
张量层   ggml/                                tensor 计算库 + 各后端(CPU/CUDA/Metal/Vulkan)
```

**最重要的一条架构认知**：现代 llama.cpp 里 `llama-cli` 只是 `llama-server` 的**薄客户端**。
真正的推理引擎集中在 `tools/server/server-context.cpp`。不要从旧版 `examples/` 出发，那里已不是主路。

### 一个循环的收官
每生成一个 token，`decode() -> post_decode()` 循环往复，直到触发停止条件
（EOS token / 生成长度 / 上下文满 / 客户端中断）。

## 逐段笔记（按上图标号）

### ① 参数解析 common/arg.cpp
- 所有 `--xxx` 参数统一解析进 `common_params params`。
- 关键子结构：`params.model`、`params.sampling`、`params.speculative`。

### ② 后端初始化
- `llama_backend_init()`：初始化 ggml 与各已编译后端。
- `llama_numa_init()`：NUMA 亲和（多路 CPU 时有用）。

### ③ 模型加载
- `llama_model_load_from_file()`：解析 GGUF 头、张量元数据，张量按需懒分配（mmap）。
- `llama_new_context_with_model()`：构造 `llama_context`，内部主要做 3 件事：
  - **KV cache**：`memory.reset(model.create_memory(...))`，按 `type_k/type_v` 与 `n_ctx × n_seq_max` 切分；显存占用大头。
  - **计算 buffer**：分两块——
    - `output_reserve()` 分配 logits / embd / sampling 视图（每条 sequence × vocab 的 float 缓冲）。
    - `sched_reserve()` 触发 scheduler 用最坏 batch 跑一次空图，把每个后端的 scratch buffer 锁到峰值。
  - **后端采样器池**：`sampling` 结构（`samplers` map 按 seq 维护 sampler chain、`token_ids_full_vocab` 全词表 id 表、logits/sampled/probs/candidates 视图）。grammar 作为 `llama_sampler_grammar` 挂在 sampler chain 上，**不是 context 独立持有的成员**。
- 产物：`server_context::impl->ctx_tgt`（目标推理上下文）。

### ④ 一次 decode 的两阶段
每秒循环里，**prompt 阶段**与**生成阶段**共用 `decode()`：
- **decode()**：把 batch 喂给 `llama_decode` → 构图 → 后端执行前向，产出 logits。
- **post_decode()**：取 logits → `common_sampler_sample` 选出下一个 token → `accept` 更新采样器状态 → 流式回发。
