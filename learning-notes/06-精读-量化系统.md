> 前置：已读 `01`，量化让 FFN/attn 的 matmul 权重变「小且可向量化」。

## 为什么量化是招牌

FFN 的权重占了模型大部分体积，且是 matmul 的乘数。把 FP32/F16 权重压缩成 4-bit/5-bit 等格式：
- 显存/带宽大降（如 Q4_0 约 4.5 bit/weight vs 16 bit）
- 权重小了，内存带宽瓶颈缓解，推理变快
- 代价是精度损失（困惑度轻微上升）

## 一、block 格式（`ggml/src/ggml-common.h`）

量化的基本单位是 **block**（一组权重共享 scale）。以 Q4_0 为例（:184）：

```c
#define QK4_0 32                 // 一个 block 装 32 个权重
typedef struct {
    ggml_half d;                 // delta：block 的共享缩放因子
    uint8_t qs[QK4_0 / 2];       // 16 字节装 32 个 4-bit 量化值
} block_q4_0;                    // 共 18 字节 → 18*8/32 = 4.5 bit/weight
```

| 类型 | 位数 | 是否有 min 偏差 | 说明 |
|---|---|---|---|
| `Q4_0` | 4.5 bpw | 无 | 对称，最简；`d` + 4bit 值 |
| `Q4_1` | 5.0 bpw | 有 `m` | 非对称，含 min 偏差 |
| `Q5_0`/`Q5_1` | 5.5/6.0 bpw | - | 5-bit，多一组 `qh` 存第 5 位 |
| `Q8_0` | 9.0 bpw | 无 | 高精度，常用作量化时的中间类型 |
| `Q2_K`/`Q3_K`/`Q4_K`/`Q5_K`/`Q6_K` | 2.6~7 bpw | 超块 | **K 系列**：多个子 block 共享超块 scale，精度/体积折中更好 |
| `NVFP4`/`MXFP4` | 4 bpw | - | 新硬件格式（英伟达/AMD） |

> K 系列（super-block）设计：`QK_K` 个权重分成 8 个子块，每个子块有 scale/min，再套一层超块 scale。比朴素 block 更省、量化误差分布更均匀——这是 Q4_K 比 Q4_0 常用得多的原因。

## 二、量化算法（`ggml-quants.c:75` quantize_row_q4_0_ref）

对每个 block 的 32 个权重：
```c
1. 找绝对最大值 amax 及其符号 max
2. d  = max / -8                 // 缩放因子，把 max 映射到 4bit 上界附近
3. id = 1/d
4. 每个权重 xi  →  (int8)(xi * id + 8.5)   // 缩放到 [0,15]，.5 做四舍五入
5. 两个 4bit 值打包进一个 uint8_t（低位+高位<<4）
```
反量化（dequant）即 `x = (int8(qs) - 8) * d`。绝大多数量化格式都是「block 内共享 scale + 定点近似」的变体，差异在设计取舍。

## 三、编排（`llama-quant.cpp`）

### 类型选择 `llama_tensor_get_type`（:661）
逐 tensor 决定量化类型，优先级：
1. 不允许量化的张量（如 norm/embedding 的某些）保持原类型
2. 用户显式指定（`--token-embedding-type` / `--output-tensor-type` / 正则 override）
3. 否则按 `ftype` 混合策略 `llama_tensor_get_type_impl` 选型
4. 形状不兼容的 `tensor_type_fallback` 回退

### 多线程量化 `llama_tensor_quantize_impl`（:709）
- 单线程：直接 `ggml_quantize_chunk`
- 多线程：按 chunk 切分，worker 各自量化一块，`ggml_validate_row_data` 校验
- `imatrix` 传入「重要性矩阵」：校准集上每行的激活幅度，用于量化时偏置误差分布（i-quant）

## 图视角小结（和 01/03 呼应）

- 卷积/FFN 的权重在**加载时**就从 GGUF 读成量化块，matmul 时「整块读取 + 定点乘加」，正是 SIMD/GPU 喜欢的形态。
- 量化类型是 per-tensor 存于 GGUF 元数据，`f16 -> q4_0` 等转换就是跑一遍 `llama_tensor_quantize_impl`。
- 量化对「精度 vs 速度」的取舍，是 llama.cpp 相对其他推理框架最核心的差异化能力之一。
